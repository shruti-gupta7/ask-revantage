# HackerEarth submission checklist

## Required assets

- [ ] Public GitHub repository URL
- [ ] Live Vercel demo URL
- [ ] `ask-revantage-hackathon.tar.gz` or `.zip` with source and run instructions
- [ ] README with prerequisites and commands
- [ ] AI-generated code/content disclosure
- [ ] Synthetic-data declaration
- [ ] Five-minute pitch and two-minute Q&A preparation

## Judging alignment

| Criterion | Evidence in the project |
|---|---|
| Solution and design | Premium dual-workspace experience; grounded answer and escalation journey |
| Business value | Measurable self-service, time-saving, routing and content-gap hypotheses |
| Innovation / AI | Confidence-aware retrieval, citations, responsible refusal and feedback loop |
| Future scalability | Replaceable adapters and Microsoft-first target architecture |
| Deployability | Next.js, Vercel config, health route, CI and environment template |
| Feasibility / completeness | Functional end-to-end demo with source addition, Q&A and requests |
| Pitch / storytelling | Five-minute script, demo sequence, metrics and pilot ask |

## Final safety review

- [ ] Run `npm run data-check`
- [ ] Confirm every demo person, policy, request and metric is synthetic
- [ ] Confirm `.env`, `.env.local`, `.vercel` and `.git` are excluded from the archive
- [ ] Confirm there are no screenshots or logs containing real information
- [ ] Confirm the public repository contains no production endpoint or credential
- [ ] Confirm the live demo warns users not to enter real data
